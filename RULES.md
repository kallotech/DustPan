# Project rules — DustPan

- Do not move, delete or overwrite personal files solely because they appear stale.
- For the app, distinguish proposed moves in the UI from filesystem changes; verify actual behavior before claiming it moves or renames files.
- For Desktop organisation, inspect the current folder map, use the deepest clearly matching existing destination, and check collisions before each rename or move.
- Preserve different-content copies and keep uncertain classifications in place or in a review area.
- Keep credentials, recovery codes, hidden files, `secrets`, and active project material outside routine filing.
- Append a privacy-preserving record of actual file changes to the Desktop organisation log. Do not disclose sensitive document contents in logs or summaries.
- Do not commit machine-specific absolute paths, local Desktop names, automation locations, credentials, or private operational history. Review current files and Git history before public release.
- Repository visibility and releases require an explicit user request; inspect the exact commit and remote state before publishing.

These project rules do not grant permission beyond the current request.
