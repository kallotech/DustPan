# Project status — DustPan

**Updated:** 2026-10-07

## macOS app

**Observed:** The app is now a native Desktop sorter. The left side searches and multi-selects visible Desktop files and ordinary folders, with a resizable Quick Look preview below the list; the right side navigates the existing University, Career, Personal, and Work folders and keeps Bin pinned above them. Core destination and review folders, hidden items, symbolic links, and names matching common credential/access terms are omitted. Single-clicking a destination files the selection; double-clicking browses. Rename has explicit Rename/Cancel buttons. Existing destinations are never overwritten, and the latest successful move or Bin action can be undone. Actual moves, renames, and undos append paths to the Desktop Organisation Log.

**Verification (2026-10-05):** `xcodebuild` built the updated app from a disposable local copy of the project. The first launch stayed responsive but its Desktop scan remained blocked until Desktop was selected in the app's folder picker; after selection, the interface loaded the visible files. The listing now runs off the UI thread, uses a filename-only directory read before metadata lookup, shows a loading state, and keeps a `Choose Desktop…` recovery button available. The resizable Quick Look pane was visually verified rendering a selected image. No Desktop items were moved or renamed; the move/undo flow remains untested. The synced project location can still stall Xcode file coordination, so the successful Xcode build used the disposable local copy.

**Quick filing and rename update (2026-10-05):** Destination rows now move the selected Desktop files on a single click and open a folder on a double-click. With one file selected, the Desktop pane offers Rename (also available with Command-Shift-R); the inline editor keeps the extension, rejects invalid/protected names, checks for an existing destination before renaming, and records successful renames in the organisation log. `swift build` passed after these changes. The click/double-click and rename interactions have not yet been exercised against disposable files, so no personal files were changed during verification.

**Bin and rename-button update (2026-10-05):** Rename editing now has explicit Rename and Cancel buttons. A pinned Bin destination stays visible above the folder list at every browsing depth; it uses macOS Trash and records the returned path so the existing Undo action can restore files. `swift build` passed, and a temporary-file Bin/Undo round-trip passed. No Desktop files were moved or renamed; the new controls have not yet been visually exercised in the app.

**Desktop folder visibility (2026-10-05):** The left pane now includes ordinary Desktop folders as selectable items, while keeping the four core destinations and review/cleanup folders out of the source list. Symbolic links, hidden items, and protected names remain omitted. Folder-to-self or folder-into-descendant moves are blocked. A fresh-scratch `swift build` passed; an Xcode build from a local source copy passed and was installed. The reopened app's accessibility view showed 10 Desktop items, all identified as folders. No Desktop item was moved or renamed during this check.

**Hide items from DustPan (2026-10-05):** Added a Hide button for selected items and a per-item “Hide from DustPan” context-menu action. A Hidden toolbar list can restore items later. This only saves their paths in DustPan preferences; it does not change Finder visibility, move files, or log a filesystem change. `swift build` and a fresh Xcode build from a temporary local copy both passed. The updated app was installed in the user's Applications folder; the previous app copy was retained recoverably in Trash. One user-selected Desktop folder was added to DustPan's hidden list without opening or changing it. The desktop automation/control tool could not attach to the app window, so the rendered controls and resulting visible list were not visually verified. No Desktop files were moved, renamed, or deleted.

**App icon (2026-10-05):** Added an editable orange two-pane vector master at `AppResources/AppIcon.svg` and macOS icon sizes in `AppAssets.xcassets/AppIcon.appiconset`. Xcode builds the catalog as `Assets.car` and writes `CFBundleIconName = AppIcon` into the app Info.plist. A fresh Xcode build and Swift package build passed; the built app's icon registration and code signature were verified. The updated app was installed and reopened; the prior install was retained recoverably in Trash. The artwork preview was inspected, but the Dock/Finder rendering was not independently checked.

**Folder-scoped Unhide all (2026-10-05):** Added an `Unhide all (n)` toolbar action for paths hidden directly within the currently selected source folder (`desktopURL`). It removes only those app-preference entries; it does not touch the files or hidden entries in other folders. The fresh Xcode build and `swift build` passed. The updated app was installed; the prior app copy was preserved recoverably in Trash. Existing hidden-item preferences were left unchanged. The updated controls were not visually inspected.
